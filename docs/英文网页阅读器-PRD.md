# 英文网页阅读器 · 产品需求文档

> 状态：功能定义定稿
> 日期：2026-10-04（2026-10-05 收窄定位：通用双语阅读器 → 英文网页阅读器）

---

## 1. 一句话定位

**给一个英文网页链接，还你一篇干净的、左右对照的双语文章；好文章可以收进书架，随时回来看。**

它是什么：一个**英文网页双语阅读器**——阅读不需要账号，**保存才需要**。登录后解锁「我的书架」。

**产品边界（垂直定位，也是本产品的取舍核心）**：

- **源语言固定英文**，译文语言可选（见 3.1）
- 只服务**英文网页**这一个场景。不做中译英、不做任意语言互译、不做 PDF / 文档 / 视频
- 粘进来的如果不是英文网页，**不翻译**，降级为单栏原文阅读（见 3.3）。这不是缺陷，是把力气集中在一件事上的主动取舍

它不是什么：
- 不是翻译工具 —— 目标不是"翻译一段文字"，而是"读完一篇英文文章"
- 不是通用翻译器 —— 一旦什么语言都接，"为英文场景优化"这件事就做不深了
- 不是纯稍后读 —— 书架是辅助，不追求"收得多"，追求"读得完"
- 不是浏览器插件 —— 不侵入原页面，不需要安装

---

## 2. 目标用户与核心场景

**主要用户**：需要大量阅读**英文**资料的开发者、研究者、学生、行业分析师；以中文母语读者为主。

**典型内容形态**（均为英文站点）：技术博客、官方文档、arXiv 论文、行业报告、Newsletter。

**两个核心场景**：

1. **当场读完**：拿到一个长文链接，想专心把它读完并看懂。
2. **先存后读**（需登录）：刷到一篇好文章但当下没空读，先收进书架，回头再读。

**为什么现有方案不够好**：

| 现有方案 | 用户的不满 |
|---|---|
| 浏览器自带翻译 | 只剩译文，无法对照原文；术语和长难句容易翻错，无从核对 |
| 浏览器插件（沉浸式翻译等） | 要安装、要配置；在乱糟糟的原页面上读；**天然没有内容管理** |
| 复制到翻译工具 | 格式全丢，长文要来回粘贴，累 |
| 浏览器书签 | 只能存链接，读的时候还是要再走一遍翻译流程 |

**本产品的立足点**：不跟插件比"能翻多少种东西"，只做一件事——**把一篇英文文章变成干净的对照阅读页，并且让你找得回来**。

## 3. 功能清单

### 3.1 输入解析
- 粘贴网址，**协议头按需补全**：
  - 已带协议头（`http://`、`https://`）→ 原样使用，不做任何改写
  - 未带协议头（如 `example.com/post`）→ 自动补 `https://`
  - 其他协议（`ftp://`、`file://` 等）→ **不补协议头**，按用户输入的协议原样尝试访问；能打开就正常处理，打不开则报错并说明原因

  > **现实约束（必须在实现时遵守）**：现代浏览器（Chrome / Edge 88 起）已移除 FTP 支持；`file://` 是本地文件协议，服务端抓取读不到用户本机文件。**服务端抓取禁止访问 `file://`** —— 否则任何访问者都能读服务器本地文件，属安全红线。
  > 因此此条的实际效果约等于：`ftp://`、`file://` 一律报"不支持的协议"。

- **目标语言选择**：源语言固定英文，所以列表里**不含 English**，共 10 种：

  | 分组 | 语言 |
  |---|---|
  | 中文系 | **简体中文（默认）** / 繁體中文 |
  | 亚洲 | 日本語 / 한국어 |
  | 欧洲 | Français / Deutsch / Español / Português / Italiano / Русский |

- 支持 `?url=xxx&lang=xx` 参数直达；未带 `lang` 时按默认语言（简体中文）处理

### 3.2 正文提取
**保留**：标题、作者、来源站点、H1–H4 小标题、段落、有序/无序列表、引用块、代码块、图片及图注。

**丢弃**：导航栏、侧边栏、广告位、相关推荐、评论区、页脚、弹窗。

### 3.3 语言判定与对照翻译

**先判定，再决定翻不翻。** 抓取完成后判定页面主语言，这是垂直定位落到功能上的第一道分叉：

| 判定结果 | 行为 |
|---|---|
| **是英文页面** | 进入下面的对照翻译流程（完整形态） |
| **不是英文页面** | **不翻译**。降级为**单栏原文阅读**：只显示原文，不做左右对照；不显示译文栏、模式切换、翻译进度。页面顶部给出一条说明（"这不是英文网页，仅显示原文"）。其余阅读能力（字号、深浅色、导出、收藏）照常可用 |

**非英文页面为什么不报错而是降级**：用户粘错了链接，至少还能当阅读器把这篇读完，不必打断他。**代价只有一个流程**——相比英文页面，少的就是"翻译"这一步，其余（抓取、正文提取、排版、阅读体验）完全复用。

**英文页面的翻译行为**：
- 按内容块严格对齐：左原文、右译文
- **逐段独立翻译**：某段失败不影响其他段
- 流式回填：译文边生成边显示
- 并发执行，控制并发数避免限流
- 代码块不翻译，原样保留
- 专有名词、产品名、技术术语保持准确

### 3.4 我的书架（需登录）

**前提**：书架只在登录后提供。未登录时阅读功能完整可用，但**不提供任何本地书架**——避免出现"本地一份、云端一份"两套存储路径。
未登录时「收藏」按钮**仍然可见**，点击后提示"登录后即可保存"。不做软强制：不主动弹登录框、不在阅读过程中打断。

**入口**：顶栏右侧「我的书架」，打开网站第一眼仍是输入框，书架是并列入口。

**添加**：
- 阅读文章时点「收藏」，自动带入标题与网址
- 书架页手动添加：输入网址；标题可留空（自动抓取原站标题作为默认），也可自定义

**管理**：
- 改标题（任何时候都能改）
- 删除单条
- 已读 / 未读状态：**纯手动切换**

**列表展示**：标题（为主）、添加时间、未读标记（小圆点）。

**排序**：最近添加在前。

**打开**：点击条目 → 载入该文章的对照阅读页。

**空态**：提示如何添加第一篇文章。

### 3.5 阅读体验
- 三种显示模式：双语对照（默认）/ 仅译文 / 仅原文
  - **非英文页面不提供模式切换**：只有单栏原文一种形态（见 3.3）
- **正文字号调节**：工具栏提供 `A-` / `A+` 两个按钮，步进缩放正文，左右两栏同步生效
- 行级对齐，天然滚动同步；悬停时左右两栏同时高亮
- 响应式：窄屏自动上下堆叠
- 浅色为主，**支持切换深色**

### 3.6 实用功能
- **阅读偏好记忆**：字号、显示模式、深浅色三项调过的值存本地，下次打开沿用（**与登录无关**，未登录同样可用）
- **结果缓存**：同一链接 + 同一目标语言，第二次打开直接出结果，不重复消耗上游额度（缓存放**服务端**，可跨用户共享）
- 一键复制译文
- 导出 Markdown（原文 + 译文；非英文页面导出单栏原文）
- 打印 / 存 PDF

### 3.7 数据存放与账号边界

**一句话**：**阅读不需要账号，只有"保存"才需要账号。**

| 数据 | 存放位置 | 需要登录 | 跨设备 |
|---|---|---|---|
| 阅读偏好（字号 / 显示模式 / 深浅色） | 浏览器本地 | 否 | 否——它是"这台设备"的显示喜好，同步反而是坏事 |
| 翻译缓存 | **服务端**（不含任何用户数据） | 否 | 不涉及——纯粹用于复用结果、减少上游调用 |
| 书架（收藏 / 标题 / 已读） | 云端 | **是** | 是 |

**为什么不提供"未登录的本地书架"**：那会引入两条持久化路径——书架的每一次增删改都要先判断"当前是否登录"，再分别走本地或云端；同时登录时还要额外写一套本地与云端的合并逻辑（按网址去重、添加时间取谁、标题冲突取谁）。这条链路一旦上线就长期存在，而收益仅仅是"未登录也能收藏"。因此首版**主动放弃**，换取实现与心智上的确定性。

**原则**：不登录也能**完整读完**一篇文章（核心体验不能被账号挡住）；账号只用来承载"需要留下痕迹"的能力。不主动弹登录框、不在阅读过程中打断。

### 3.8 异常处理
- 抓取失败要**分类说明原因**：不支持的协议 / 反爬 / 需要登录 / JS 动态渲染 / 超时 / 不是网页
- 翻译侧要区分：额度不足 / 授权失败 / 模型不可用
- **非英文页面不算异常**：走 3.3 的降级路径（单栏原文 + 一条说明），不弹错误、不打断阅读

**原则**：宁可诚实报错并说明原因，也不返回半截内容假装成功。

## 4. 书架数据模型

| 字段 | 类型 | 说明 |
|---|---|---|
| id | 主键 | 唯一标识 |
| url | 文本 | 文章地址（去重依据） |
| title | 文本 | 标题，用户可自定义；默认取原站标题 |
| status | 枚举 | `unread` / `read`，由用户手动切换 |
| created_at | 时间 | 添加时间，排序依据 |
| owner_id | 文本 | 数据归属与隔离，由数据库依据登录身份自动填充，客户端不传 |

> 不设来源域名字段：书架列表只以标题呈现。
> 该表**仅存在于登录后的场景**，未登录时不存在任何本地镜像。

## 5. 首版明确不做

| 不做 | 理由 |
|---|---|
| **阅读强制登录** | 输入链接、对照阅读、调字号、导出全都不需要账号，账号只用于书架 |
| **非英文网页的翻译** | 定位垂直在英文网页。粘入其他语言时降级为单栏原文（§3.3），不做通用翻译 |
| **中译英 / 任意语言互译** | 源语言固定英文，这是"把英文场景做深"的前提；什么都接就什么都做不深 |
| **未登录的本地书架** | 会引入本地/云端两套持久化路径与后续合并逻辑，收益仅是"未登录也能收藏" |
| **已读状态自动标记** | 系统无法判断用户是否真的"读完"，自动标记反而制造噪音 |
| **书架显示来源域名** | 列表中标题才是识别信息，域名是冗余信息 |
| PDF / EPUB / 文档上传 | 那是插件的主场，重且杂 |
| 视频字幕、图片 OCR、漫画 | 同上，技术复杂度高 |
| 浏览器插件 | 要处理登录态、动态 DOM、样式注入，工程量完全不同 |
| 多翻译引擎切换 | 只用一个最好的，少一个配置项少一半复杂度 |
| 高亮标注、生词本 | 会把产品拖向"学习工具"，偏离定位 |
| 书架分组、标签、搜索 | 书架条目少时用不上；等条目多了再考虑 |

**取舍原则**：宁可做一个场景做透，不做十个场景都做一半。

## 6. 已知限制与风险

1. **反爬是最大风险**。付费墙、强反爬站点、纯 JS 渲染的 SPA 都会抓取失败。策略是**诚实报错并说明原因**。
2. **不登录无法保存收藏**。书架是账号能力，未登录时收藏入口提示登录。这是主动的设计取舍，不是缺陷。
3. **翻译质量依赖模型**，需明确标注"译文由 AI 生成，仅供参考"。
4. **无法覆盖登录后内容**。这是插件的能力，主动放弃。
5. **版权边界**。产品只做个人阅读辅助，**不存储原文正文**，只存标题和链接，不建立内容库。
6. **非英文网页不翻译**。粘入中文 / 日文等页面时只显示原文单栏，不提供译文。这是垂直定位的主动取舍，不是能力缺失。
7. **语言判定会有误判**。中英混排、以英文标题配中文正文、代码占比很高的技术页都可能判错。策略与误判兜底见技术方案。

## 7. 怎样算成功

1. **自己每天会用** —— 读英文资料时第一反应是丢进这个阅读器，书架里真的存着自己要读的东西。
2. **跑通完整链路** —— 经历"idea → 功能定义 → 技术选型 → 开发 → 上线 → 拿到可分享链接"的全过程。**这是本次最重要的产出。**
3. **有真实用户反馈** —— 分享出去后有人真的用，并能说出哪里好、哪里不行。

**不以"打败沉浸式翻译"为目标。** 它在功能覆盖上不可战胜，本产品的价值在于把单一场景做到体验更好。

## 8. 后续可演进方向（不在首版）

- 书架搜索、分组、标签
- 阅读进度记忆（读到哪一段）
- 生词高亮与查词
- 摘要生成（先看要点再决定读不读）
- 分享对照页链接给他人
- 浏览器书签批量导入
